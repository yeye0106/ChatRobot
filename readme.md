# 📝 纯前端多轮对话助手 (LLM) 开发需求清单

> **项目概述**：本项目要求实现一个基于纯前端技术栈的多轮对话 AI 助手。项目需脱离传统后端架构，直接通过浏览器与大语言模型进行安全、流畅的交互。

## 一、 核心架构与技术栈

* **开发语言**：仅使用 **HTML + CSS + JavaScript** 编写静态文件。
* **架构限制**：纯前端架构，**无**后端服务、**无**数据库、**无**登录系统、**无**服务器请求转发。
* **接口规范**：接入**阿里云百炼**平台提供的 OpenAI 兼容接口。
* **模型选择**：推荐选择高性价比（经济实惠）的基础模型进行调用。

---

## 二、 必选功能模块（验收标准）

此部分为基础及格线，请确保在最终交付件中完整实现以下全部功能：

1.  **界面基础**：醒目的页面标题与易懂的用户操作说明。
2.  **凭证管理**：提供专用的 **API Key 输入框**（由使用者在界面上手动填写）。
3.  **交互输入**：清晰可见的文本输入区与“发送/生成”触发按钮。
4.  **内容展示**：独立的**对话历史展示区**，需直观区分用户与 AI 的消息内容。
5.  **状态反馈**：请求过程中的**加载中（Loading）提示**界面。
6.  **异常处理**：完善的**错误提示机制**（准确拦截并提示 API Key 错误、网络断开、接口异常等场景）。
7.  **会话控制**：提供**清空对话 / 重新开始**的一键重置按钮。
8.  **核心逻辑**：实现真实的**多轮对话**机制（每次 API 请求必须封装并携带历史消息数组，确保模型具备上下文记忆能力）。

---

## 三、 🔑 密钥安全绝对红线

**任何违反以下安全规范的行为，将直接视为严重违规：**

* **严禁硬编码**：绝对不允许将 API Key 写死在 HTML、CSS 或 JavaScript 代码中。
* **严禁代码泄露**：绝对不允许将包含真实 API Key 的文件提交、上传至 GitHub 或任何公开平台。
* **本地存储限制**：默认情况下，用户填写的凭证仅可暂存于**浏览器内存**中（即页面刷新后失效），**严禁**使用 `localStorage` 等方式持久化到本地以防他人窃取。
* **进阶扩展（选做）**：在确保绝对安全的前提下，允许利用 Supabase 等第三方免费云数据库进行高安全级别的存储验证，但此项不作强制要求。
